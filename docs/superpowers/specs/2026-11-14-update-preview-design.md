# アップデートのプレビューモード 設計

## 目的

`swift run` のデバッグ版でも、アップデートウィンドウの全状態(新しい版あり・更新中・完了・エラー)を
本物の Homebrew や Colima に触れずに画面で確認できるようにする。今のデバッグ版では Hako 欄が
「.app として動いていない」、Colima 欄は新版が出るまで「最新」になり、更新ボタンまでたどり着けない。

## ゴール

- 環境変数 `HAKO_UPDATE_PREVIEW` を付けて起動したときだけ、仮想のアップデートを表示する
  - Hako: 0.6 → 0.7、Colima: 今の版 → 0.99.0。変更内容は見本の Markdown
  - メニューバーの「新しいバージョン X があります」も出し、そこからウィンドウを開けることも確かめられる
- 「アップデート」を押すと、本物の brew の代わりに約 2 秒かかる偽の処理が動き、値で結果を変えられる
  - `1`: 成功 / `fail`: 「アップデートに失敗しました」/ `lag`: 「Homebrew にまだ反映されていません」
- 完了後の「再起動」「Colima を再起動」は、プレビュー中は何もせずウィンドウを閉じるだけ
  (「Colima を再起動」は VM が動いている前提で表示する)

## 非ゴール / アンチゴール

- 設定画面などから切り替えられるようにすること(利用者の目に触れるため)
- プレビュー中に本物の brew・xattr・colima の操作・Hako の再起動が走ること
- 環境変数なしのときの動作が少しでも変わること

## 選んだ作り方

`HAKO_DEMO` と同じく環境変数で切り替える。プレビュー用の値は `UpdateModel.Backend` と
`StatusStore` の更新確認に差し込み、偽の brew は既存の `HomebrewUpdater.Runner` の差し替えで作る。
外した案: 開発ビルド用の隠しメニュー(コードの分岐が増え、配布版にも残る)。

## 実装者に任せること

- 見本の変更内容の文面、偽の処理の待ち時間の作り方
- 認識できない値(例: `HAKO_UPDATE_PREVIEW=foo`)は `1` と同じ扱いにする
